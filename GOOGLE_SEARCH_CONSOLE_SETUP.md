# Налаштування Google Search Console (GSC)

Цей документ пояснює, як підключити сайт ODUDLAB до Google Search Console
після запуску на реальному домені. Виконати ці кроки має **власник** — вони
вимагають доступу до акаунта Google та до DNS/хостингу, тому їх не можна
автоматизувати наперед.

> **Важливо.** Токен верифікації тут **не вигадано**. У коді підготовлено
> лише «порожнє гніздо» під нього (env-змінна `GOOGLE_SITE_VERIFICATION`).
> Реальне значення ви отримаєте від Google на кроці 3 і вставите самі.

---

## Передумови

1. **Сайт задеплоєно на реальному домені** через HTTPS (наприклад
   `https://odudlab.com`). Поки хостинг/домен на паузі — цей крок
   заблоковано, і GSC підключати ще нема до чого.
2. Змінна оточення `NEXT_PUBLIC_SITE_URL` виставлена на цей самий домен
   (без слеша в кінці). Від неї залежать канонічні URL, `sitemap.xml`
   та Open Graph — якщо вона неправильна, Google проіндексує неправильні
   адреси.
3. Обліковий запис Google, з якого ви керуватимете сайтом.

---

## Крок 1. Створити ресурс (property)

1. Відкрийте <https://search.google.com/search-console>.
2. Натисніть **Додати ресурс** (Add property).
3. Оберіть тип ресурсу:
   - **Домен (Domain)** — рекомендовано. Покриває всі піддомени та обидва
     протоколи (http/https) одразу. Верифікація лише через DNS (див. Спосіб В).
   - **Префікс URL (URL prefix)** — простіше верифікувати (метатег або файл),
     але покриває лише точну адресу, яку ви ввели. Тоді вводьте саме
     `https://odudlab.com` (той самий `NEXT_PUBLIC_SITE_URL`).

---

## Крок 2. Обрати спосіб верифікації

Достатньо **одного** зі способів нижче. Якщо обрали тип «Домен» — доступний
лише **Спосіб В (DNS)**.

### Спосіб А — HTML-метатег (найпростіший для типу «Префікс URL»)

У проєкті вже все підготовлено — вам треба лише вставити токен у змінну
оточення, і метатег зʼявиться сам.

1. У GSC оберіть спосіб **HTML tag**. Google покаже рядок виду:
   ```html
   <meta name="google-site-verification" content="ABC123...тут-ваш-токен" />
   ```
2. Скопіюйте **лише значення `content`** (частину `ABC123...`).
3. На хостингу задайте змінну оточення:
   ```
   GOOGLE_SITE_VERIFICATION=ABC123...тут-ваш-токен
   ```
   (шаблон уже є в `.env.example`).
4. Передеплойте сайт. Тег зʼявиться в `<head>` кожної сторінки — це робить
   функція `generateMetadata` у `src/app/[locale]/layout.tsx`
   (поле `verification.google`), без хардкоду токена.
5. Поверніться в GSC і натисніть **Verify**.

> Перевірити локально/на проді, що тег на місці:
>
> ```bash
> curl -s https://odudlab.com | grep google-site-verification
> ```

### Спосіб Б — Завантаження HTML-файлу

1. У GSC оберіть **HTML file**, завантажте запропонований файл
   `googleXXXX.html`.
2. Покладіть цей файл у теку `public/` проєкту (Next віддає її вміст із
   кореня домену). Після деплою він буде доступний за
   `https://odudlab.com/googleXXXX.html`.
3. Натисніть **Verify**.

### Спосіб В — DNS TXT-запис (обовʼязковий для типу «Домен»)

1. У GSC оберіть **DNS**. Google покаже TXT-запис виду
   `google-site-verification=XYZ...`.
2. У панелі реєстратора/DNS-провайдера додайте **TXT-запис** для кореня
   домену (`@`) з цим значенням.
3. Зачекайте на поширення DNS (від кількох хвилин до кількох годин) і
   натисніть **Verify**.

---

## Крок 3. Надіслати карту сайту (sitemap)

Після успішної верифікації:

1. У GSC відкрийте розділ **Sitemaps** (Карти сайту).
2. Додайте адресу: `sitemap.xml`
   (повна адреса — `https://odudlab.com/sitemap.xml`).
3. Натисніть **Submit**.

Карта вже генерується автоматично (`src/app/sitemap.ts`) і вказана в
`robots.txt` (`src/app/robots.ts`), тож окремо нічого налаштовувати не треба —
достатньо один раз повідомити про неї Google.

> Перевірити, що карта віддається:
>
> ```bash
> curl -s https://odudlab.com/sitemap.xml | head
> curl -s https://odudlab.com/robots.txt
> ```

---

## Крок 4. Перевірки після підключення (перші дні)

- **Індексація** → розділ _Pages (Сторінки)_: скільки URL проіндексовано,
  чи немає масових помилок.
- **Покриття redirect-ів**: старі адреси з `LEGACY_REDIRECTS` мають вести на
  нові сторінки кодом 301, а не 404. Точкова перевірка через
  _URL Inspection_ (Перевірка URL) для кількох старих адрес.
- **Core Web Vitals** → розділ _Core Web Vitals_: реальні польові дані
  зʼявляються не одразу — потрібно ~28 днів накопичення трафіку. До того
  орієнтуйтесь на лабораторні виміри (PageSpeed Insights).
- **Мобільна зручність / Досвід сторінки** — перегляньте попередження, якщо
  зʼявляться.

## Пов'язані налаштування

| Що                                    | Де                                              | Стан                         |
| ------------------------------------- | ----------------------------------------------- | ---------------------------- |
| Метатег верифікації                   | `GOOGLE_SITE_VERIFICATION` (env) → `layout.tsx` | Гніздо готове, токен за вами |
| `sitemap.xml`                         | `src/app/sitemap.ts`                            | Готово, автогенерація        |
| `robots.txt` (+ посилання на sitemap) | `src/app/robots.ts`                             | Готово                       |
| Канонічний домен / OG / sitemap URL   | `NEXT_PUBLIC_SITE_URL` (env)                    | Виставити на реальний домен  |
| Google Analytics 4 (окремо від GSC)   | `NEXT_PUBLIC_GA_MEASUREMENT_ID` (env)           | Гніздо готове, ID за вами    |

---

## Часті помилки

- **Верифікація зникла** — не видаляйте метатег/DNS-запис/файл після
  верифікації: Google періодично перевіряє його повторно.
- **Неправильний домен у канонічних URL** — майже завжди означає, що
  `NEXT_PUBLIC_SITE_URL` не оновили після деплою.
- **`www` проти без `www`** — оберіть одну канонічну форму й переконайтесь,
  що інша віддає 301-редирект на неї. Для типу ресурсу «Домен» це неважливо.
